# ORIGEN V2 policy-domain to receipt-modality binding

Status: RESEARCH ONLY / SYNTHETIC FIXTURES / NOT A DEPLOYMENT TRUST ANCHOR

## Defect

The V2 policy envelope signs a `policy_domain`, but the composition accepted
any caller-supplied expected domain. The V1 receipt parser, meanwhile, only
accepts `target.modality == "CLASSIC"`. A correctly signed policy for the
De las Tres namespace could therefore be supplied alongside a CLASSIC receipt
and pass the policy-domain comparison. The receipt remained CLASSIC, but the
composition did not enforce that its trust-policy namespace was CLASSIC too.

This is a semantic cross-domain mismatch, not a signature forgery.

## Change

The V1 receipt composition now requires the exact domain
`origen.chispazo.classic.provenance` after verifying the signed V2 envelope
and before verifying the receipt signature. It also checks the parsed verified
receipt modality is exactly `CLASSIC` as defense in depth.

A validly signed De las Tres-domain policy is rejected even when the caller
supplies that same De las Tres domain as `expected_policy_domain`.

The V1 receipt schema and the independent provenance adapter are unchanged.
A future De las Tres evidence path requires a separate receipt schema and an
explicit, reviewed mapping between that schema's modality and its signed
policy domain. It must not reuse the CLASSIC V1 composition.

## Synthetic adversarial tests

- CLASSIC receipt + CLASSIC V2 domain: signature chain may be inspected, but
  final provenance remains `BLOCKED_PROVENANCE`.
- CLASSIC receipt + correctly signed De las Tres V2 domain: rejected.
- CLASSIC receipt + another correctly signed domain: rejected.

All keys and receipt bytes are generated by tests. No institutional key,
actual contest receipt, draw record, or physical evidence is represented.

## Remaining boundary

Root key, key ID, expected domain, sequence floor and clock remain
caller-supplied. There is no persistent monotonic store, out-of-band root
provisioning, authenticated clock, revocation freshness, institutional
authorization, ledger verification, witness quorum, nested physical
signatures or independent custody. `verify_independent_provenance` remains
fail-closed at `BLOCKED_PROVENANCE`.

Production remains `BLOCKED / RESEARCH_ONLY_NO_EDGE`.
